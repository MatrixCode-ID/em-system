# EmSys.Ui.Wpf.Core 0.1.0-alpha.7

Date: 2026-10-08
Previous: 0.1.0-alpha.6

## Summary
The main window gets a status bar that hosts can fill, with the product version in a fixed slot. Role changes for a stored user are saved right away, Switch User shows accounts as cards, and debug tools move to the top of the Tools list. Scroll bars and unselected tab captions now follow the light and dark theme.

## Breaking changes

- On the Roles tab of the user editor, switching a role or changing its Start or Expiry date for a user that is already stored is now saved immediately, card by card, instead of waiting for **Save**. A new user still sends its role cards together with **Save**, after the user is created.
- Every `ScrollBar` without a style of its own now uses the engine's thin themed scroll bar, set at application level by `EmApp.Run`. A host that relied on the stock WPF scroll bar now gets the engine's look; give a scroll bar an explicit style to keep a different one.

## New features

- **Status bar** under the content of the main window (`TabbedMainWindow`), filled through `EmApp.MainWindow.Vm.StatusBar` (`MainStatusBarVm`): `Text`, `LeftItems`, `RightItems`, and `IsVisible`. The `SystemItems` area belongs to the engine. Windows torn off from a tab do not show it. The control itself is `EmStatusBar`.
- **Product version** in the engine's area of the status bar (`StatusVersionItem`): `v1.3.0-alpha.1`, or `dev` for a development build, with a tooltip and a copy command. It reads `AppVersion` from `EmSys.Libs`.
- The publisher passes a container's version tag on as the product version: the `APP_VERSION` build argument for Dockerfile and Compose builds (unless the profile already sets it), and `-p:Version` for template builds. Tags that are not versions, such as `latest`, are not passed.
- **Switch User** shows accounts as a grid of cards with a coloured avatar per kind of account (System, Admin, User), chips for kind, state, and `CURRENT`, and a check mark on the selected card. A strip under the banner shows the account in use with a one-click **Back to debugger** button. The administrator card appears only when the server reports that the account is switched on (`GetMeta_AdminAccountEnabled`); it is hidden when that cannot be checked.
- Role cards being saved show a spinner and are locked; an invalid period is held until it is corrected, and a card that failed keeps its mark so it can be sent again by switching it or with **Save Changes**.
- Connection Config, Switch User, and Simulate Login are at the top of the shared Tools list, followed by a separator, on the single-page home and in the multi-tab Tools menu. The multi-tab Tools menu also shows each tool's icon.

## Fixes

- Scroll bars no longer appear light on the dark theme. The themed vertical and horizontal styles live in `Styles/ScrollBars.xaml` (also merged by `MaterialDesign.xaml`); `materialVerticalScrollBarStyle` moved there from `Progress.xaml`, which still merges it.
- Unselected tab captions in the user editor and the exception detail dialog use the theme's text colour instead of black.

## Upgrade notes

- Switch User needs an API server with `EmSys.Api.Core` 0.1.0-alpha.7 to show the administrator card; with an older server the card stays hidden.
- No database migration is required for this release.
