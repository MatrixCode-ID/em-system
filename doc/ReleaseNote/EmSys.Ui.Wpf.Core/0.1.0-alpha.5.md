# EmSys.Ui.Wpf.Core 0.1.0-alpha.5

Date: 2026-10-07
Previous: 0.1.0-alpha.4

## Summary
Container Manager now configures Docker deployment targets, deploys images, and shows history with rollback. The publisher adds deployment after push and retry, clearer profile forms, and channel-based floating tags; navigation now follows the server's declared modules.

## Breaking changes

- `ContainerTarget.ExtraTags` is removed. Update code that sets additional tags to use the Standard tagging rules, or choose Manual tagging for a custom tag. Old profile JSON can still be read, but its extra tags are no longer used.
- After server claims load, navigation whose module or required claim is absent from the catalog is hidden and cannot be opened, including by administrators and in debug mode. Hosts must declare the module and claims for those screens to remain available.

## New features

- Container Manager adds a DEPLOY card and themed dialogs for SSH or Portainer target configuration, connection tests, stack creation, manual deployment, history, and rollback. The WPF `ICtnServices` client implements the deployment contracts in `EmSys.Libs` and uses longer request timeouts for deployment operations.
- Container profiles have a **Deploy after push** option, enabled by default. After pushing to the Built-in registry, the publisher requests deployment of successfully pushed images. Deployment failure is recorded separately from publish success, and **Retry deploy** retries failed deployments.
- Standard tagging pushes the version tag followed by its floating tags: the channel tag for a prerelease; `release`, `latest`, `A.B`, and `A` for a release. Manual tagging accepts a custom tag and pushes no floating tags; version tags and reserved floating tags cannot be entered as manual tags.
- The tagging mode is chosen when a profile is created. Version/channel or manual tag input is on the Publish strip; Compose keeps its per-service tags in the profile form.
- Publish profile forms group Mode with Source, show Template fields only when relevant, and include help icons for Source, Target, and Advanced options. Profile and related publisher dialogs use themed `EmWindow` chrome.
- A toolbar **Tools** dialog reports the tools required by the selected profile, their versions, and repair hints. The Publish page gives more space to Source and Target.

## Upgrade notes

- Upgrade the backend and shared packages together, and apply the backend database migration before using deployment. See [EmSys.Api.Core upgrade notes](../EmSys.Api.Core/0.1.0-alpha.5.md#upgrade-notes).
- Existing container profiles also default **Deploy after push** to enabled. Review this option and the container's active deployment target before the next Built-in registry push; turn it off in Advanced when automatic deployment is not wanted. Custom registries are skipped.
- Review profiles that previously used extra tags or custom tags. Standard mode manages version and floating tags; create a Manual profile for a custom tag. See the [publisher guide](../../engine/engine-publish.md).

## Usage notes

- The package now generates an XML documentation file for IntelliSense.
