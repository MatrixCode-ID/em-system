# EmSys.Ui.Wpf.Core 0.1.0-alpha.18

Date: 2026-10-26
Previous: 0.1.0-alpha.17

## Summary
Add approval-wrapper routing and batch actions, Android APK release preparation, and versioned release-note controls for Release Manager and publishing. Release screens show the published server release, validate prepared artifact versions, and keep release notes in a dedicated side panel. Debug sign-in and simulation exit are available from the login screen.

## Breaking changes

- Release-format types are supplied by `EmSys.Ui.Core` under `Em.Ui.Core.Release.Format` instead of `Em.Ui.Wpf.Core.Release`. Update imports and rebuild custom release integrations.
- System void and reinstate operations require a reason of at least 15 characters after trimming. The full Approval Manager is restricted to administrative/debug access; ordinary users use module wrappers or the authorized request viewer.
- With release-note lock enabled, the notes folder must be an existing absolute path on the current machine. Older relative values are not converted automatically.

## New features

- Register module-owned approval wrappers with `AddApprovalWrapper`. MY TASKS opens the registered wrapper, with an authorized viewer fallback when none is registered.
- Approval proxies expose System batch signing/voiding, Data batch decisions/withdrawals, and year/month queries. System batch UI captures the current active level and displays individual results.
- Release Manager supports Windows and Android profiles. Android preparation discovers the host identity and required tooling, creates or imports a permanent keystore, prepares a signed arm64 APK, and publishes signed update metadata and installation links.
- Release-note lock automatically selects the highest unreleased versioned note and creates the next empty template after publication. A valid Summary is required for Sync; Prepare and launcher builds remain available while a note is incomplete. Container publishing requires a valid note before Build or Push.
- Release notes open in a shared side panel with history, refresh, and maximize/restore controls. Notes folders remain independent of the profile location and can be on another drive.
- Release Manager reads the published server release when selecting or refreshing a profile, even when no local prepared folder exists. Compare and Sync validate the version of the actual prepared artifact.
- Distribution preparation uses stable build paths and excludes commit-dependent SourceLink metadata; source provenance is written beside the prepared distribution.
- Debug Sign In creates an account session through the debug-only API. Login screens provide cancellation back to SYSTEM DEBUGGER while simulation is available.

## Fixes

- Release settings keep Save/Cancel available while scrolling, surface the CDN address configuration, and handle platform-specific identity, Java, SDK, and signing settings.
- Published version information no longer substitutes local prepared state for missing server metadata. Legacy manifests and network errors have explicit display states.
- Release-note validation checks that prepared versions match the selected note before Sync; incomplete notes no longer block Prepare unnecessarily.

## Upgrade notes

- Update all EmSys packages to `0.1.0-alpha.18` and use the matching backend for the new approval and debug sign-in actions.
- Review each locked release/publish profile's notes folder on the machine that performs the release. The highest unreleased note determines its release version; fill its Summary before publication.
- Back up Android keystores and manifest signing keys, keep the application ID and signing certificate stable, and publish a higher version code for each Android update. Folder targets also need a public release URL for installation links.
- Android environment installation and real device installation/update require separate verification. Existing profile JSON without a platform remains a Windows profile.
- No database migration is required relative to `0.1.0-alpha.17`. This is an unpublished release candidate; publication is a separate operation.
