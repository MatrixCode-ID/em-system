# EmSys.Api.Core 0.1.0-alpha.14

Date: 2026-10-21
Previous: 0.1.0-alpha.13

## Summary
Stack deploy targets can write the deployed image name into the compose file (tag and digest, or tag only) instead of an image variable, over SSH and in Portainer.

## New features

- Stack deploys follow the target's `ImageRef` (EmSys.Libs). With an image name, each deploy rewrites only the value of the service's `image:` line, in the compose file on the SSH host or in the Portainer stack file, and keeps the stack environment as it is; the old file is kept in the run's history. With `Variable` the behaviour is unchanged.
- The deploy passes the deployed tag to the target, so the image line shows the version. A deploy without a tag writes the digest only and logs a warning.
- Create stack and the stack template use the image name for targets that write it themselves.
- Test connection reports the current image line of the service for targets that write the image name.

## Upgrade notes

- Database migration: run `doc/sqlscript/mssql/updates/20261021-CtnDeployImageRef.sql` before starting this version on an existing database. New installations get the column from `tables/030-registry.sql`. Existing targets keep using their image variable.
- A Portainer stack deployed from Git can only use the image variable: Test connection reports a target that writes the image name, and its deploy is refused.
- With tag only, a rollback pulls the tag as it is at that moment, so it can get a newer image if the tag was moved. Tag and digest keep rollback exact.
