# EmSys.Api.Core 0.1.0-alpha.13

Date: 2026-10-21
Previous: 0.1.0-alpha.12

## Summary
Ships the redesigned approval engine (Data Approval and System Approval, signer settings, attachments, a build-time metadata analyzer), the Business Module Manager backend, managed CDN folders with recycle bin and quota, CDN release publishing, and an option to disable the Container Manager service.

## Breaking changes

- The approval engine is rewritten. Flow declarations, document-type registration, approval PDF rendering and stamp calibration are removed; modules register Data or System approvals in `ApprovalRegistry`. Document Approval is reserved and its registration throws `NotImplementedException`. See `doc/engine/engine-approval.md` for the new registration API.
- The approval database schema changed (see Upgrade notes). Old clients and modules must be updated before deploying an API built on this version.
- The employee model is no longer part of the core context.

## New features

- System Approval with ordered steps, candidate snapshots, signatures, reinstate and void, signer settings with backups, comments (including from system accounts) and attachments stored in object storage; Data Approval works on an entity tree supplied by the owning module.
- A Roslyn analyzer shipped in the package (`analyzers/dotnet/cs`) checks approval metadata across assemblies at build time.
- `builder.AddBusinessModuleManager()` with tenant, department and employee services (claim `core.business:Business Module Manager Access`); disable with `modules.business: false` or `EM_MODULE_BUSINESS=false`.
- Contact search paging with filters applied on the server before paging.
- Managed CDN folders owned by an application, recycle bin with restore, temporary-file cleanup and per-folder quota; `ICdnReleaseServices` publishes product releases into owned folders.
- `builder.EnableContainerManager = false` omits the container management service and its actions (default `true`). Registry protocol hosting is independent.
- Services resolved from dependency injection inside a request now act on behalf of the calling user (request, `HttpContext` and abort token come from the ambient request).

## Fixes

- Deleting a role no longer fails when users are still assigned to it.
- Pins `System.Security.Cryptography.Pkcs` 10.0.13 to avoid the vulnerable version pulled in through MailKit/MimeKit.

## Upgrade notes

- Existing SQL Server databases: back up approval data, then run `doc/sqlscript/mssql/updates/20261017-ApprovalRedesign.sql`, `20261017-ApprovalSubSummary.sql` and `20261017-ApprovalSystemComments.sql`, then re-run `views/vi_ApprovalRequestStatus.sql`. **The redesign upgrade discards existing approval requests.** New databases run `tables/020-approval.sql` and the status view.
- Business Module Manager: run `tables/080-tenant.sql`, `tables/090-tenant-org.sql` and the three tenant views listed in `doc/engine/engine-business-module-manager.md`. There is no startup schema check.
