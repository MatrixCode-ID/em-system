# EmSys.Api.Core 0.1.0-alpha.3

Date: 2026-10-06
Previous: 0.1.0-alpha.2

## Summary
The container registry gains manual garbage collection and tag and manifest deletion. The server no longer stops at startup when blobs are missing from storage; it only logs a warning.

## New features
- Registry garbage collection: a review (dry run), then a run, for orphaned blobs, stale uploads, and files without metadata older than the grace period (default 24 hours, 1 to 720). Protected by the Container Manager Access claim. A second GC started while one is running is rejected with 409.
- Deleting a single tag and a single manifest through the management service. Deleting a manifest is rejected with 409 while an index manifest in the same container still references it, including on `DELETE /v2/<name>/manifests/<digest>`.
- Manifest info includes the number of blobs and the number of missing blobs.

## Fixes
- The storage check at startup no longer fails startup when blobs recorded in the database are absent from the storage folder (for example when the database is shared with another storage folder). The server keeps running and logs a warning; strict verification only applies when the storage directory is changed.

## Upgrade notes
- No database migration.
- The push guard used during GC assumes one API instance per registry storage folder.
