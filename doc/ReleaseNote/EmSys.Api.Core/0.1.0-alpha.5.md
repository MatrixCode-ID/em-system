# EmSys.Api.Core 0.1.0-alpha.5

Date: 2026-10-07
Previous: 0.1.0-alpha.4

## Summary
Adds container deployment to Docker servers over SSH or the Portainer API, with connection testing, stack creation, deployment history, and rollback. Optional module switches are now available through EmApiConfig.

## Breaking changes

- Hosts with the container registry enabled require the deployment database migration before starting this version. The registry startup check rejects an older schema; see Upgrade notes.

## New features

- One deployment target per registry container, using SSH or Portainer in Stack or standalone Container mode. Management actions use the existing Container Manager Access claim.
- Connection tests discover available targets and support server fingerprint pinning. Portainer targets can register the registry login and create a stack; SSH targets can create a compose file without overwriting an existing one.
- Deployments pull an image by digest and recreate the selected service or container. Standalone container recreation preserves its settings and attempts to restore the old container if replacement fails.
- Active targets can filter automatic deployments by tag. Manual deployment and rollback to an earlier successful run are available independently of the tag filter, with per-target concurrency protection and recorded results.
- Stored deployment credentials are encrypted with AES-GCM. New dependencies: SSH.NET 2026.0.0 and YamlDotNet 18.1.0.
- `EmApiConfig.Modules` and `IsModuleEnabled(name, defaultValue)` let hosts control optional modules by case-insensitive name; an unspecified module defaults to disabled unless the caller supplies another default.

## Upgrade notes

- For an existing SQL Server database, run [20261007-CtnDeploy.sql](../../sqlscript/mssql/updates/20261007-CtnDeploy.sql) before starting the upgraded registry backend. New installations use the updated registry installation script.
- Upgrade `EmSys.Libs` and the WPF client packages together. Configure a deployment target in Container Manager and ensure the Docker server can reach the registry and authenticate for pulls.
- Automatic deployment is requested by the WPF publisher after a Built-in registry push. A plain Docker or CI push does not trigger deployment. See [Deploy to Docker servers](../../engine/engine-registry.md#deploy-to-docker-servers) for prerequisites and limitations.
- The `Modules` setting is a host integration hook: hosts must call `IsModuleEnabled` when registering optional modules. The engine does not enable or disable modules automatically.

## Usage notes

- The package now generates an XML documentation file for IntelliSense.
