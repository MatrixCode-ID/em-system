# EmSys.Api.Core 0.1.0-alpha.15

Date: 2026-10-22
Previous: 0.1.0-alpha.14

## Summary
The container registry can put a tag on a manifest that is already stored, without a push, and records adding and moving tags in the audit log.

## New features

- `PostMeta_CtnTagAdd` (claim Container Manager Access) points a tag at an existing manifest of the container. No blob is uploaded and no deploy is started. A new tag is added; a tag already on another manifest of the same container moves to the chosen manifest, with the same update a push to an existing tag uses; a tag already on that manifest is left as it is. The tag must be a valid OCI tag (letters, digits, `_`, `.` and `-`, at most 128 characters, not starting with `.` or `-`), otherwise 400; a manifest outside the container gives 404, and a tag created by someone else at the same moment gives 409. Image index manifests can be tagged too.
- Audit: the `System.Registry` group gets `tag.added` and `tag.moved` entries next to `tag.deleted`, with the tag, the digest, and for a move the previous digest. Read them in the Log Manager.

## Upgrade notes

- No database update is needed.
- A client that shows the new Add tag action (EmSys.Ui.Wpf.Core 0.1.0-alpha.15) gets 404 `Action ... was not found` from an API built on an earlier version; update the API first.
