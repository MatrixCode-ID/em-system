# EmSys.Api.Core 0.1.0-alpha.16

Date: 2026-10-22
Previous: 0.1.0-alpha.15

## Summary
Runtime switches for the system storage services, a runtime CDN file size limit, replaceable skins for the home page and CDN pages, and the Container Manager claims in the server catalog.

## New features

- Runtime service switches: `IFeatureServiceServices` reads and saves the on/off state of the CDN, NuGet feed, Object Storage and Container Registry services. Reading needs the manager claim of that service; saving is for administrators only and applies immediately. A switched-off service answers its public protocol (`/cdn`, `/nuget`, `/store`, `/v2`) with 404, and the module-facing `IObjectStore` throws `ServiceDisabledException` (503); management actions stay available. CDN and registry keep the state in `settings/service.json`; NuGet and Object Storage keep it in the engine settings in the database. A missing value means enabled.
- `PostMeta_CdnMaxFileSize` (claim CDN Manager Access) changes the per-file CDN limit at runtime (1–1,048,576 MB), stored in `settings/cdn.json`. The host value is the seed; the stored value wins on the next start.
- Skins: `IEmSkin`, `EmRazorSkin`, `DefaultHomeSkin` and `DefaultCdnSkin` render the home page, favicon, CDN directory listing and not-found pages. Register a host skin once through the builder; its embedded assets are written to the reserved `.skin` folder at the CDN root before the server accepts requests. See the engine skin guide.

## Fixes

- When `EnableContainerManager` is on (the default), the claims Container Manager Access and Container Registry Settings Manage are now declared in the claim catalog next to the Container Manager actions. Before, only the actions were registered.
- A host feature that is not added (for example no `AddNuPak`) no longer has its manager or settings claims and actions in the active catalog, and its public prefix answers 404 instead of falling back to 200.

## Behaviour changes

- The welcome catch-all that answered 200 for every unknown path is gone: unknown paths, with or without an extension, now answer 404 through the skin. The root and favicon are mapped explicitly; HTML pages are served only to GET requests that accept `text/html`.
- The `.skin` folder at the CDN root is reserved: management operations cannot list, upload into, move into or extract into it.

## Upgrade notes

- No database update is needed.
- A client that shows the service switches or the CDN limit editor (EmSys.Ui.Wpf.Core 0.1.0-alpha.16) gets 404 `Action ... was not found` from an API built on an earlier version; update the API first.
