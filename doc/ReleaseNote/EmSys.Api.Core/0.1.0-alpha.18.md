# EmSys.Api.Core 0.1.0-alpha.18

Date: 2026-10-26
Previous: 0.1.0-alpha.17

## Summary
Add authorized System and Data approval batch operations, date-based approval queries, and debug-only account sign-in. Batch requests preserve individual authorization and transaction boundaries, and report partial failures without advancing into a newly activated approval level.

## Breaking changes

- All System approval voids, including reinstate, require a reason of at least 15 characters after trimming. Clients must collect and send that reason.
- The unrestricted full Approval Manager is reserved for administrative/debug access; ordinary users continue through server-authorized wrappers, request viewers, or compact views.

## New features

- Sign the caller's captured active System steps, or explicitly request administrative signing of active steps. A batch never carries on into a level activated by earlier signatures in that batch.
- Void explicitly selected System requests with per-request outcomes and the ordinary void permission checks.
- Approve, reject, or withdraw up to 200 explicitly selected Data requests independently. Conflict review remains available per request; batch operations do not override conflicts.
- `IEmApprovalData<TEntity>.AllowBatchSign` and the corresponding System definition option let module authors disable batch operations when individual review is required.
- Approval lists support date ranges, oldest-first ordering, year/month counts, and active-step/waiting-time summaries.
- Debug-token callers can create a normal account session without supplying its password through `PostGetMeta_DebugSignIn`.

## Security and compatibility

- Debug sign-in skips only the password check. Account-state checks and the enabled state of the built-in administrator still apply; callers without an authenticated debug token receive a not-found response.
- Batch decisions use the same server-side visibility, candidate, administrative, and module permission checks as individual operations. A failed request does not roll back unrelated successful requests.

## Upgrade notes
- Deploy with matching `EmSys.Libs` and UI packages at `0.1.0-alpha.18` before using the new actions.
- Modules whose client-side validation must run for every signature should disable batch signing in their approval definition.
- No database migration is required relative to `0.1.0-alpha.17`. This is an unpublished release candidate; publication is a separate operation.
