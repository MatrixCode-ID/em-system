# EmSys.Ui.Core 0.1.0-alpha.18

Date: 2026-10-26
Previous: 0.1.0-alpha.17

## Summary
Provide cross-platform release manifest and signature types, verified Android update checks and downloads, and a shared approval-wrapper navigation catalog. Signed release metadata can now identify both Windows launcher releases and Android APK updates.

## Breaking changes

- Release-format types move from `Em.Ui.Wpf.Core.Release` to `Em.Ui.Core.Release.Format` in this package. Update namespace imports and rebuild code that reads, writes, or verifies release manifests and signatures.

## New features

- The shared manifest supports optional application version metadata and Android package identity, version name/code, minimum supported version code, and APK filename. Existing manifests without the optional version remain readable.
- `ReleaseUpdateSource` reads an embedded release URL and public key from the host assembly.
- `ReleaseUpdateChecker` verifies the manifest signature before interpreting Android update policy, distinguishes optional and mandatory updates, and verifies downloaded APK size and SHA-256.
- `ApprovalWrapperCatalog` maps MY TASKS approval groups to module-owned navigations. When no wrapper is registered, it routes to the authorized request viewer rather than the full manager.
- Typed wrapper navigation payloads and an optional refresh hook let an already-open module apply a new approval filter.

## Upgrade notes
- Update namespace imports and keep all EmSys packages on `0.1.0-alpha.18`.
- Android update sources require the full release-folder URL, including the trailing slash, and the matching public manifest key. Builds without both metadata values have no configured update source.
- No database migration is required. This is an unpublished release candidate; publication is a separate operation.
