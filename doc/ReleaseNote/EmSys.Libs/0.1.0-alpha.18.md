# EmSys.Libs 0.1.0-alpha.18

Date: 2026-10-26
Previous: 0.1.0-alpha.17

## Summary
Add shared contracts for approval wrappers, System and Data batch operations, approval date filtering, and debug-only account sign-in. Clients can inspect per-request batch results and opt out of batch signing when module-specific review is required.

## Breaking changes

- Custom implementations of `IApprovalServices` must implement the new batch and year/month query actions. Custom implementations of `ICredentialServices` must implement `PostGetMeta_DebugSignIn`; the packaged API and UI proxies already provide these members.
- `ApprovalQuery` and `ApprovalCapability` have additional positional record members. Existing constructor calls can use the defaults, but custom deconstruction, mocks, and generated clients may need updating.

## New features

- System approval contracts support signing a captured active level and voiding explicitly selected requests, with individual success/failure results. `ApprovalSignAllScope` distinguishes the caller's candidate steps from administrative signing.
- Data approval contracts support approve, reject, and withdraw operations over explicitly selected request IDs, without batch conflict overrides.
- `IEmApprovalSystem.AllowBatchSign` lets a definition disable server-side batch signing. Capabilities expose that decision to clients.
- Approval queries support date ranges and oldest-first ordering, with a separate year/month count action and display-only active-step/waiting-time information.
- `ApprovalRules.MinVoidReasonLength` shares the 15-character minimum reason for System voids, including reinstate.
- `PostGetMeta_DebugSignIn` defines password-free account sign-in for authenticated debug-token callers; ordinary sign-in rules still apply.

## Upgrade notes
- Update all EmSys packages together to `0.1.0-alpha.18`, and update custom service implementations before rebuilding.
- System void and reinstate callers must provide a reason of at least 15 characters after trimming.
- No database migration is required relative to `0.1.0-alpha.17`. This is an unpublished release candidate; publication is a separate operation.
