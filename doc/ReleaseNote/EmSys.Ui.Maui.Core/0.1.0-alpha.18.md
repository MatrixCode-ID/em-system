# EmSys.Ui.Maui.Core 0.1.0-alpha.18

Date: 2026-10-26
Previous: 0.1.0-alpha.17

## Summary
Add mobile approval lists and viewers, MY TASKS navigation, and verified Android application updates before login and through manual checks. Improve account identity restoration and debug login simulation, including a visible return to SYSTEM DEBUGGER without replacing a saved normal session.

## New features

- Mobile approval screens support authorized Data and System request review, signer information, decisions, comments, attachments, and module-owned System document views.
- Register System editors and approval wrappers through the MAUI builder. MY TASKS routes approval groups to module-owned wrappers or the authorized request viewer, and management tools are grouped in the account panel.
- Service proxies expose the new System/Data batch operations and approval year/month queries. Modules can consume per-request results while keeping individual conflict review available.
- Android hosts can check signed updates before login or session restore and manually from login/account screens. Optional updates offer Later; mandatory updates block entry until an update is installed or the application exits.
- APK downloads show progress, support cancellation and retry, and verify signed size/hash before handing installation to Android. The engine declares installation permission and handles Android's user-confirmation flow.
- Package build targets emit the host application identity for isolated preferences and logs. Release Manager embeds the release address and verification key for prepared Android builds.
- Debug Sign In is available from the login screen, with Cancel simulation and Return to SD paths that preserve the separately saved normal session.

## Fixes

- Account identity and badges are refreshed after Android activity recreation.
- Simulated account login clears debugger identity before loading the authenticated user and claims, including when an API service was already used before sign-in.
- Leaving a simulated session restores SYSTEM DEBUGGER without saving over or deleting the ordinary login session.

## Upgrade notes

- Update all EmSys packages to `0.1.0-alpha.18` and deploy the matching API for approval batch actions and debug sign-in.
- Hosts should provide a permanent Android application ID and `EmAppId`. Existing hosts without embedded identity retain the application-name storage fallback; preferences are not migrated automatically.
- Prepared update builds need an embedded full release-folder URL and public manifest key. Builds without that pair do not perform update checks. Startup check failures allow login; manual checks display the failure.
- Verify `REQUEST_INSTALL_PACKAGES` in the consuming host's merged Android manifest. Android 8 and later may require the user to allow installation from this source, and updates must use the same signing certificate as the installed application.
- The release flow currently produces arm64 APKs; it does not add a Play Store/AAB, downgrade, or background-update workflow. Real device installation and update remain separate validation steps.
- Mobile System void/reinstate UI remains unavailable. No database migration is required relative to `0.1.0-alpha.17`.
- This is an unpublished release candidate; publication is a separate operation.
